# Qarzhy: GitHub + Vercel

Это инструкция для закрытого тестового запуска. Публикация ещё не выполнена. Перед подключением Git-интеграции ознакомьтесь с [результатами проверки](PUBLICATION.md). Репозиторий: https://github.com/bekasyl-karshygauly/qarzhy.

## 1. Подготовьте отдельную базу

Нужна внешняя PostgreSQL с постоянным хранением, TLS и ICU-сортировкой `und-x-icu`. Локальная база на 127.0.0.1 недоступна функциям Vercel. Встроенный PostgreSQL из `npm run db:local` предназначен только для этого компьютера.

Для первого интернет-теста используйте новую базу с вымышленными операциями. Существующая локальная база и аккаунт сами в GitHub или Vercel не переносятся. Не загружайте дамп в репозиторий. Для реальных персональных данных отдельно определите размещение основной базы, резервных копий, логов и условия трансграничной обработки: [PRIVACY-KZ.md](PRIVACY-KZ.md). У Vercel в опубликованном списке регионов нет региона Казахстана; даже казахстанская база сама по себе не устраняет обработку серверной функцией за рубежом.

Для serverless предпочтителен поддерживаемый поставщиком пулер. Для Prisma 6 используйте параметры `sslmode=require&sslaccept=strict`, для начального пилота — `connection_limit=1&pool_timeout=10`. Сертификат должен быть доверенным. Если провайдер требует особый сертификат или иные параметры пулера, настройте их по его документации; не отключайте проверку TLS. `npm run check:vercel` проверяет конфигурацию, но не соединение и не наличие ICU.

## 2. Выполните миграции и создайте первый аккаунт

Сначала сделайте резервную копию, если целевая база уже содержит данные. Для новой базы выполните `prisma migrate deploy` с приватной строкой прямого административного подключения. Не используйте для миграций пулер, который их не поддерживает. Автоматическая Vercel-сборка намеренно не изменяет схему базы.

Один способ на этом компьютере: создайте игнорируемый файл `.env.migrate` со строкой `DATABASE_URL` для целевой базы и выполните:

```powershell
node --env-file=.env.migrate node_modules/prisma/build/index.js migrate deploy
```

Не задавайте эту строку в команде и не присылайте её в чат. Предварительно убедитесь, что в текущем терминале нет ранее заданной `DATABASE_URL`: Node не переопределяет существующие переменные значениями из env-файла. Веб-приложению достаточно отдельной роли с необходимыми правами на рабочие таблицы; миграционной роли нужны права изменения схемы.

На Vercel регистрация закрыта (`ALLOW_REGISTRATION=false`). Для создания первого аккаунта в **новой тестовой облачной базе** можно временно запустить существующую форму регистрации только на локальном интерфейсе. Создайте игнорируемый `.env.bootstrap`:

```dotenv
DATABASE_URL=REPLACE_WITH_PRIVATE_APPROVED_TEST_DATABASE_URL
HOSTNAME=localhost
PORT=3112
APP_URL=http://localhost:3112
COOKIE_SECURE=false
ALLOW_REGISTRATION=true
```

Это шаблон, а не рабочие реквизиты. Не включайте здесь Gemini и не копируйте содержимое файла в Git. После успешной сборки и копирования `public` и `.next/static` в `.next/standalone`:

```powershell
node --env-file=.env.bootstrap .next/standalone/server.js
```

Откройте http://localhost:3112 и зарегистрируйтесь обычной формой с собственным паролем. Адрес `localhost` отделяет временную cookie от текущего сайта на 127.0.0.1; не открывайте этот сервер на 0.0.0.0. Проверьте в терминале фактический адрес запуска. Завершите процесс после регистрации. Не переносите эти временные `APP_URL`, `COOKIE_SECURE` и `ALLOW_REGISTRATION` в Vercel. Если переменные уже заданы в терминале, сначала уберите их из этого терминала. Для копирования ресурсов в готовую standalone-сборку без запуска локального сервера:

```powershell
New-Item .next/standalone/public -ItemType Directory -Force | Out-Null
Copy-Item public/* .next/standalone/public -Recurse -Force
New-Item .next/standalone/.next/static -ItemType Directory -Force | Out-Null
Copy-Item .next/static/* .next/standalone/.next/static -Recurse -Force
```

## 3. Импортируйте репозиторий в Vercel

После проверки состава коммита и одобрения публикации загрузите код в GitHub. В Vercel выберите **Add New → Project**, подключите GitHub и импортируйте `bekasyl-karshygauly/qarzhy`. Если репозиторий приватный, предоставьте интеграции доступ только к нужному репозиторию.

Параметры проекта:

- Framework: **Next.js**, Root Directory: корень репозитория.
- Node.js: **24.x** (также указан в `.nvmrc`).
- Install Command: `npm ci`.
- Build Command: `npm run build:vercel` (задан в `vercel.json`).
- Output Directory: стандартный для Next.js; не задавайте `out` и не включайте статический экспорт.
- Включите предоставление **System Environment Variables** в настройках проекта.

Добавьте переменные из `.env.vercel.example` приватно через интерфейс Vercel. Обязательны рабочая внешняя `DATABASE_URL`, `COOKIE_SECURE=true`, `ALLOW_REGISTRATION=false`, реальные `DATA_OPERATOR_NAME` и `DATA_OPERATOR_CONTACT`. Приложение не использует `NEXT_PUBLIC_` для ключей и паролей. Не загружайте заполненный env-файл в GitHub.

`APP_URL` можно оставить пустым: production использует точный `VERCEL_PROJECT_PRODUCTION_URL`, preview — точный `VERCEL_URL`. Это доверенные переменные платформы, а не заголовки запроса. При собственном домене можно явно задать `APP_URL=https://ваш-домен` без пути. Не назначайте production-адрес окружению Preview: его изменяющие запросы будут отклоняться защитой Origin. Используйте выбранный канонический URL; альтернативный alias также может получить 403. Не добавляйте wildcard для всех сайтов `.vercel.app`.

Preview должен использовать **отдельную тестовую БД**, отдельный аккаунт и, если нужен, отдельный ключ ИИ. Не открывайте preview доступ к реальным production-данным. В настройках доступа включите доступную вашему тарифу защиту deployment; она не заменяет вход в приложение.

Первый Deploy выполняйте после миграций и создания аккаунта. Если сборка остановится на `check:vercel`, исправьте перечисленные настройки и запустите Redeploy. Не убирайте проверку для обхода сообщения.

## 4. ИИ — по желанию

Без `AI_API_KEY` финансовые функции работают, а ИИ честно показывает отсутствие провайдера. Для подключения Gemini добавьте серверные параметры из шаблона и свой ключ через Vercel. Бесплатный/неподтверждённый Gemini остаётся в общем учебном режиме без автоматического чтения финансов аккаунта. Пользователь отдельно сохраняет согласие в настройках. Голос для этого провайдера не подключён (`VOICE_MODEL` пуст). Подписка на приложение Gemini не подтверждает платный API.

ИИ уже имеет общий таймаут 45 секунд; маршрут оставляет до 60 секунд для обработки и БД. Квоты провайдера и ограничения тарифа Vercel проверяются в соответствующих кабинетах. Ключи и реальные запросы не нужны GitHub Actions.

## 5. Проверьте публичную ссылку

1. `/api/health` отвечает успешно; затем войдите подготовленным аккаунтом. Не публикуйте диагностические реквизиты.
2. Создайте вымышленный доход и расход, проверьте точный баланс, обновите страницу и проверьте сохранение. Проверьте кошельки, перевод, поиск и графики.
3. Проверьте бюджеты, календарь, CSV, экспорт и удаление отдельного тестового аккаунта. Ошибки БД/ICU требуют исправления хостинга, а не удаления поиска.
4. Проверьте GSAP, WebGL или предусмотренный fallback, reduced motion, кнопки, модальные окна, консоль и мобильную ширину.
5. На телефоне откройте HTTPS-ссылку и установите PWA. Без сети остаётся только нейтральный offline-экран; приватные данные не кешируются. Фоновые push-уведомления не подключены.
6. Проверьте `/privacy`, операторские сведения, закрытую регистрацию, настройки доступа, резервное копирование и восстановление на отдельной базе. ИИ тестируйте только после своего согласия и без конфиденциальных сведений.

После подключения Vercel Git Integration новые push/PR обычно создают deployment автоматически. Workflow `Verify Qarzhy` выполняет проверки и **сам ничего не публикует**. Чтобы проверка была обязательна до изменения production-ветки, настройте PR и required status check в правилах GitHub (если доступны вашему тарифу), а не рассчитывайте на порядок независимых сборок Vercel и Actions.

Для регулярной эксплуатации также настройте отдельный доверенный запуск `scripts/cleanup.mjs` для истёкших сессий и лимитов, мониторинг и резервные копии с проверкой восстановления. В этом изменении cron и внешнее резервное хранилище не подключались. Скрипт обслуживания не должен получать ключи через публичный URL.
