# Проверка публикации Qarzhy — 22 октября 2026

**GitHub Pages несовместим с полным Qarzhy.** Подготовлен вариант **GitHub для кода + Vercel для Next.js + отдельная PostgreSQL**. До согласования и настройки внешних сервисов сайт не опубликован. Публичная рабочая ссылка пока не создана.

## Архитектура и совместимость

| Часть | Реализация | GitHub Pages | Vercel + PostgreSQL |
|---|---|---|---|
| Интерфейс | Next.js 16.4.2 App Router, React 19, TypeScript, Tailwind CSS | Только самостоятельная статика | Поддерживается |
| API и защита | Динамический `/api/[...path]`, GET/POST/PATCH/DELETE, Node.js, Zod, Origin, ограничения запросов | Нет серверного исполнения | Поддерживается |
| Авторизация | scrypt, серверные сессии PostgreSQL, HttpOnly cookie | Не работает | Сохраняется |
| Учёт и аналитика | Prisma 6.19.3, PostgreSQL, BigInt в тиынах, Recharts 3 | Нет базы и записей API | Требуется внешняя БД с ICU |
| ИИ | Серверный Gemini proxy и отдельное согласие | Нельзя безопасно хранить и использовать ключ | Серверные env; ключ необязателен |
| Движение | GSAP 3 / ScrollTrigger, Motion 12, Three.js / GLSL | Сама клиентская графика переносима | Сохраняется |
| PWA | Manifest, service worker, install icons, offline fallback | Статические части переносимы | Полная онлайн-функциональность через HTTPS |
| Политика и заголовки | Runtime `/privacy`, CSP и другие серверные headers | Нужна другая серверная среда | Сохраняется |

Статический экспорт Next.js не предоставляет request-specific API, серверные cookie и операции записи. Поэтому `output: 'standalone'` оставлен; `output: 'export'`, Pages-workflow и отключение API не добавлены. Совместимость установлена по исходникам и установленному руководству Next.js по static exports; отдельная экспериментальная сборка `output: 'export'` не выполнялась.

Пути `/api`, `/_next`, `/brand`, `/icons`, `/sw.js` рассчитаны на корень домена и подходят стандартному размещению Next.js на Vercel. GitHub Pages проекта располагается под `/qarzhy/`; один `basePath` не решает отсутствие сервера. Переписывать ресурсы под неподходящий хостинг не требуется.

Прокрутка остаётся нативной. Lenis в зависимостях нет. Существующие motion/WebGL-компоненты, финансовые вычисления, формы, графики и согласия не переписывались. Новая серверная адаптация касается доверенного адреса окружения и времени выполнения маршрута.

## Что подготовлено

Локальный `origin` привязан к предоставленному репозиторию. Все 116 проверенных исходных файлов подготовлены в Git index для первого коммита. Коммит и push не выполнялись; при проверке удалённого репозитория ветки и теги не обнаружены.

- `vercel.json`, `.nvmrc`, `.env.vercel.example`, команды `check:vercel` / `build:vercel` и [пошаговая инструкция](VERCEL.md).
- Один точный Origin из явного `APP_URL` либо доверенных системных env Vercel. Production и Preview разделены. Подстановка request Host, wildcard и доверие чужим preview-доменам не используются.
- Проверка конфигурации перед Vercel-сборкой: HTTPS, удалённая БД с TLS и проверкой сертификата, secure cookie, явно заданный режим регистрации и сведения об операторе. По умолчанию регистрация закрыта (`ALLOW_REGISTRATION=false`); явно заданное `true` разрешает создание аккаунтов, см. [инструкцию](VERCEL.md#открытие-и-закрытие-регистрации). Это проверка настроек, а не доказательство доступности БД или юридического соответствия.
- GitHub Actions с отдельной временной PostgreSQL: проверка состава файлов, `npm ci`, unit-тесты, миграции, production build, Chromium и e2e. Официальные Actions закреплены полными SHA. Без production-секретов, live Gemini, выкладки дампов и автодеплоя.
- Предпубликационная проверка исходников `npm run check:publish`: приватные пути, известные локальные ключи/строки и сигнатуры ключей. Значения секретов не выводятся. Это не полный аудит секретов и не проверка истории Git.

`.env`, `.env.production`, другие заполненные env, `.local-db`, `.design`, `.superdesign`, `.vercel`, `.next`, `node_modules`, отчёты, логи, дампы, резервные копии, ключи и внутренний `docs/PROJECT-STATUS.md` исключены. В репозиторий разрешены только три пустых шаблона: `.env.example`, `.env.production.example`, `.env.vercel.example`. Работающие локальные финансы не входят в исходники и не переносятся автоматически.

CI на GitHub и реальный deployment Vercel пока не запускались; Docker-сборка на этом компьютере не проверена, Docker недоступен. Playwright выполнялся с одним worker и без принудительного отключения GPU. Локальные диагностические JSON и скриншоты остаются в игнорируемых `.design`/`test-results`. Проверки JavaScript/шейдеров не выявили runtime-ошибок в проверенных сценариях. После первого размещения обязательно проверить внешнюю БД, миграции, Origin, TLS, cookie, доступ к аккаунту и PWA на реальном телефоне.

## Что требуется от владельца перед публикацией

1. Проверить подготовленные файлы и одобрить отправку кода в [репозиторий Qarzhy](https://github.com/bekasyl-karshygauly/qarzhy). Не включать GitHub Pages. Лучше начать с приватного репозитория.
2. Подключить GitHub к своему аккаунту Vercel и импортировать репозиторий; либо установить и подключить доступный плагин Vercel для дальнейшей настройки из чата. Никакие доступы не считаются предоставленными заранее.
3. Выбрать одобренную внешнюю PostgreSQL. Для первого теста использовать новую базу и вымышленные записи. Preview отделить от production. Выполнить миграции и создать первый аккаунт по инструкции; для закрытого теста оставить `ALLOW_REGISTRATION=false`. Самостоятельная регистрация включается отдельно явным `true` и новой публикацией, без изменения режима обработки данных или ИИ.
4. Ввести env приватно в Vercel, заполнить оператора и проверить условия обработки. Пароли, API-ключи и строки подключения в чат не отправлять.
5. После успешной выкладки проверить сайт по реальной HTTPS-ссылке. Публичная ссылка на страницу входа не означает готовность к открытой регистрации или обслуживанию всего Казахстана.

## Ограничения и персональные данные

Нет банковской интеграции, автоматических списаний, фоновых push, верификации email и восстановления пароля. Голос Gemini не подключён по принятому решению. Бесплатный Gemini работает в общем учебном режиме; согласие пользователя не включается автоматически. Эти функции не были отключены ради хостинга.

По действующему закону Казахстана хранение персональных данных связано с базой/цифровым объектом на территории Казахстана (статья 12); трансграничная передача регулируется отдельно (статья 16). В опубликованном списке регионов Vercel нет Казахстана. Для реальных финансов нужны отдельная проверка размещения базы, копий, серверной обработки и оснований передачи, а также правдивые сведения об операторе. Подготовка к Vercel не является заключением о соответствии законодательству. Локальные пользовательские данные за рубеж не отправлялись.
